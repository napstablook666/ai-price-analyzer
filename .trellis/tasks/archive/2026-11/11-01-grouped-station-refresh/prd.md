# 按分组刷新站点

## Goal

让“刷新全部”只作用于当前比较模式下已启用的站点，避免用户在“付费中转站”和“公益站”之间切换后误刷新另一类站点；同时让预检、采集、进度、错误和完成提示都明确对应的站点分组。

## Background and confirmed behavior

- EditHere 反馈要求“刷新全部”跟随当前选择的部分，并将站点分为“付费中转站”和“公益站”。
- 仪表盘已经支持 `comparisonMode`：`paid` 表示付费中转站，`public` 表示公益站；当前模式会过滤报价、摘要、筛选项、付费专属控件和站点错误。
- 当前“刷新全部”的预检和实际刷新仍使用所有已启用站点，刷新确认、进度和完成提示也使用“全部启用站点”的语义。
- 站点已有 `category` 字段，规范值为 `paid` 或 `public`；缺失或非法值按现有规则归一为 `paid`。
- “刷新当前站点”已有独立入口，按站点筛选器和 `stationId` 工作，不属于本次范围调整。
- 用户已确认“当前选择的部分”仅指当前比较模式，不叠加站点筛选器、供应商筛选或分组筛选。

## Requirements

### R1. “刷新全部”按比较模式取站点

- `paid` 模式只允许已启用且 `category = paid` 的站点进入刷新范围。
- `public` 模式只允许已启用且 `category = public` 的站点进入刷新范围。
- 禁用站点无论所属分组，都不得参与预检、采集、进度统计、错误统计或快照更新。
- 站点范围由服务工作线程根据当前持久化设置和站点配置计算，前端不得通过自报站点 ID 扩大范围。

### R2. 预检、确认和实际刷新使用同一范围

- `REFRESH_PREFLIGHT`、确认令牌校验、`REFRESH_ALL`、刷新进度和完成摘要必须使用同一分组站点集合。
- 预检结果中不得出现当前比较模式之外的站点。
- 预检确认令牌必须绑定当前比较模式和当前分组站点配置；模式切换、启用状态变化或站点配置变化后，旧令牌必须要求重新预检。
- 没有可刷新的启用站点时，不得调用站点采集或启动空的 `REFRESH_ALL`。

### R3. 两个模式的数据保持隔离

- 付费模式刷新不得清除、覆盖或重建公益模式已有的快照和报价；公益模式刷新同理。
- 刷新完成后，仪表盘仍只展示当前模式的数据，另一模式的历史数据继续保留。
- 当前模式之外的站点不得生成新的刷新快照，也不得出现在本次刷新错误或进度列表中。

### R4. 刷新界面反馈与数量一致

- 刷新预检、进度、完成提示应明确显示“付费中转站”或“公益站”。
- 预检和进度显示当前分组的启用站点数量，数量必须与实际调度集合一致。
- 当前分组没有启用站点时，界面显示可理解的空状态，并明确未发起刷新。
- 模式切换后，刷新范围、分组标签、数量和预检状态立即跟随新模式；旧模式的预检结果不能继续用于确认。

### R5. 保持单站刷新兼容

- “刷新当前站点”继续只刷新站点筛选器选中的启用站点，不因比较模式之外的站点存在而改变语义。
- 单站刷新继续遵守现有刷新进行中的互斥、确认和按钮锁定逻辑。
- 本次改动不得把站点筛选器、供应商筛选或比较模式之外的站点列表强行合并到“刷新全部”范围。

## Acceptance Criteria

- [x] 在 `paid` 模式点击“刷新全部”时，预检、实际采集、进度、错误和完成摘要只包含启用的付费中转站。
- [x] 在 `public` 模式点击“刷新全部”时，预检、实际采集、进度、错误和完成摘要只包含启用的公益站。
- [x] 当前模式之外的站点不会发起请求、写入新的刷新快照，或出现在当前刷新列表中。
- [x] 切换模式后刷新范围立即跟随新模式；另一模式已有快照和报价保持不变。
- [x] 预检令牌绑定模式和站点范围；范围发生变化时确认被拒绝并要求重新预检。
- [x] 刷新界面明确显示当前分组和启用站点数量；空分组不发起刷新并显示提示。
- [x] “刷新当前站点”行为保持不变，禁用站点不能被刷新。
- [x] 现有付费模式、公益模式、站点错误隔离、刷新确认和刷新并发测试继续通过，并补充分组范围、空分组和令牌失效测试。

## Out of scope

- 不改变 `paid` / `public` 分类规则、站点预设、价格归一化或价格比较算法。
- 不改变“刷新当前站点”的业务含义。
- 不新增第三种比较模式。
- 不删除另一分组的历史快照，不强制清空另一分组的缓存。
- 不把站点筛选器、供应商筛选或其他临时筛选条件变成“刷新全部”的范围条件。
