# 模型匹配 🔗

各家站点对同一个模型的叫法不一样：`claude-3-5-sonnet-20241022`、`Claude 3.5 Sonnet`、`anthropic/claude-3.5-sonnet`、`[官方] claude sonnet 4`。比价表能合并成一行，靠的是匹配流程。

## 目标

把站点的原始模型名落到一个**规范模型 id**（例如 `claude-sonnet-4`）。只有落到同一个 id，不同站点才进同一行。

## 归一化

匹配前先把名字洗干净：

1. 去掉方括号前缀，如 `[官转] `、`[限时] `。
2. 去掉日期后缀，如 `-expires-on-2024-06-20`、`-20241022`。
3. 转小写，全角符号转半角。
4. 去掉供应商前缀，如 `openai/`、`anthropic/`、`google/`。

```js
normalizedModelName = modelName.toLowerCase()
  .replace(/^(?:\[[^\]]*\]\s*)+/, "")
  .replace(/-expires-on-\d{4}(?:-\d{2}-\d{2})?$/, "");
```

这是人工覆盖项保存时的归一规则，规则引擎用的是同一套。

## 优先级

从高到低，命中即停：

| 顺序 | 来源 | 说明 |
| --- | --- | --- |
| 1 | 人工确认 | `modelMatchOverrides`，你自己指定的映射，置信度 `1` |
| 2 | 插件拼写 | `plugins/<id>/models.json` 里登记的别名，置信度 `0.95` |
| 3 | AI 判定 | 判定队列里接受过的写法，置信度 `0.8`；排在内置规则链之前，命中后不会再进入规则链 |
| 4 | 规范模型 | 规范模型表里的名字与别名，走下面的规则链 |
| 5 | 内置规则 | 项目固定执行，当前只启用精确名称 |

人工覆盖永远最高。插件别名跟着插件走，插件更新会覆盖你没手改过的部分。

## 内置规则链

| id | 规则 | 当前状态 | 做什么 |
| --- | --- | --- | --- |
| `exact` | 精确名称 | 启用 | 归一后完全相等 |
| `suffix` | 后缀/供应商 | 固定关闭 | 允许带供应商前缀、渠道后缀 |
| `ignore_version` | 忽略版本号 | 固定关闭 | 丢掉 `-v1`、`-0613` 之类 |
| `fuzzy` | 模糊匹配 | 固定关闭 | 编辑距离近似 |

当前项目固定只启用精确匹配，宁可漏也不认错。其余规则保留在核心实现中，但不对用户开放开关，由项目版本统一调整。

## 匹配置信度

| 置信度 | 来源 | 表现 |
| --- | --- | --- |
| 高 | 人工确认（1.0）、插件拼写（0.95） | 正常显示 |
| 中 | AI 判定（0.8） | 显示但可被覆盖 |
| 低 | 项目保留的非精确规则（当前关闭） | 由项目版本统一调整 |

置信度不改变价格本身的采集结果，只影响这一行有多可信。

## 人工覆盖

在站点行的「模型」列上点选，从候选里挑一个基准模型，就写进 `modelMatchOverrides`：

```js
{ stationId: "s2api", modelName: "claude 3.5 sonnet (20241022)", officialModelId: "claude-3-5-sonnet" }
```

同一个「站点 + 归一后模型名」只保留一条，重复设置会覆盖。

## 调优顺序
1. 先看有多少行未匹配，超过两三成再动手。
2. 配好模型服务后在判定队列跑一次「识别当前未匹配」，接受的结果会写成人工确认。
3. 剩下的高频模型在判定队列点行尾「修改」，输入模型关键词，从基准清单里挑一条就写成人工覆盖，不用手打 id。
4. 如果发现固定规则误合并或误拆分，记录原始模型名并反馈项目规则。
