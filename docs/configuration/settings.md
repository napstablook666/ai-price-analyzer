# 偏好与成本 ⚙️

「偏好与成本」里的设置决定了比价表怎么算、怎么排、显示什么。这里的每一项都只影响本地计算，不会改变站点数据。

## 显示与货币

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| `defaultCurrency` | `CNY` | 展示货币，可选 `CNY` / `USD` |
| `exchangeRate` | `7.3` | 人民币兑美元汇率，只用于换算 |

汇率可以手填，也可以点「从中国银行刷新」拉当日牌价。填了非法值会退回 7.3。

## 比价视图

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| `comparisonMode` | `paid` | `paid` 看付费中转站，`public` 看公益站 |

两种视图共用同一份采集数据，只是筛选范围不同。切换视图会改变「刷新全部」的目标集合。

## 推荐门槛

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| `evidenceThreshold` | `60` | 匹配置信度低于该值的报价不参与推荐 |

旧版的 `recommendationProfile` 已废弃，读取时会被清理掉。推荐不再做成本与证据的加权打分，同一模型里只在国内付费站、官方匹配、成本可算的报价中挑最便宜的那条，其余按证据门槛标「需核验」或「可选」。口径见[成本与推荐](../guide/cost#推荐)。

## 月用量

`usage` 是一组 11 个字段，全部按 token 计（图片按张）。取值默认不是拍脑袋来的，是一段真实用量按 30 天折算：

| 字段 | 默认值 |
| --- | --- |
| `input` | 382.95 M |
| `cacheRead` | 2946.28 M |
| `cacheWrite` | 0 |
| `cacheWrite1h` | 0 |
| `output` | 30.74 M |
| `requests` | 45,494 |
| `peakShare` | 7/24 ≈ 0.29 |
| `imageInputTokens` / `imageOutputTokens` / `images` | 0 |

预设：

| id | 名称 | 内容 |
| --- | --- | --- |
| `measured` | 实测月用量 | 上表测出的那一组 |
| `recent30d` | magpie-30天 | 按 magpie 记录最近 30 天的用量折算成月用量 |
| `recent7d` | magpie-7天 | 按最近 7 天用量折算，变动大的月份更敏感 |
| `baseline` | 基础估算 | 3000 万输入 / 600 万输出，其余默认 |
| `custom` | 自定义 | 先选预设再逐项改 |

`peakShare` 是 0 到 1 的比例，不是百分比数字。填 `7` 会被夹到 `1`。

负值、空值、非数字一律落回预设默认值，不做报错。

## 匹配

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| `matchingRules` | 只开「精确名称」 | 四条规则，可逐条开关 |
| `modelMatchOverrides` | 空 | 人工指定「站点模型 → 官方模型」 |
| `showUnmatched` | 开 | 没对上官方价的行是否进表 |

匹配规则与优先级的细节见[模型匹配](./matching)。

## 站点分类

站点挂在三个分类之一：

| id | 名称 |
| --- | --- |
| `benchmark` | 基准 |
| `paid` | 付费中转站 |
| `public` | 公益中转站 |

分类决定站点进哪个视图，也决定汇总口径。「基准」站点用来做参照，不参与推荐排序。

## 关于与更新

「关于」分区放版本信息、更新检测和项目链接，数据来自 GitHub Releases，不上报任何本地数据。

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| `updateAutoCheck` | `true` | 是否按间隔在后台静默检查 |
| `updateIntervalMinutes` | `360` | 检查间隔，只接受 `60` / `360` / `1440` 分钟 |
| `updateChannel` | `stable` | `stable` 只提示正式发布，`prerelease` 连预发布一起提示 |

改动即时生效：关掉自动检查会清掉 `update-check` 定时任务，改间隔会按新周期重建。最近一次检查结果单独存 `update-state`，不写进设置，也不随导出文件走。

「检查更新」先读公开的 `github.com/<仓库>/releases/latest` 页面（`prerelease` 渠道读 `releases` 列表），从跳转后的地址或页面链接里取 tag，再和本地 `manifest.json` 的 `version` 按语义化版本比较。页面不带发布说明，所以拿到版本后还会试一次 `api.github.com` 补说明，接口不通就留空，不影响「有没有新版本」的结论。仓库还没发过版本时 GitHub 返回 404，界面显示「仓库还没有发布版本」，不当错误处理。走页面是因为未登录的接口配额只有每小时 60 次，撞上限时提示剩余恢复时间（读 `X-RateLimit-Reset`）；自动检查在恢复时间前直接跳过，不重复消耗配额。

## 不会被恢复的旧设置

老版本的 `llm`、`jev`、`providerProfiles`、`activeProviders` 在保存时会被清掉。这些功能已经下线，不要再往设置里塞回去。
