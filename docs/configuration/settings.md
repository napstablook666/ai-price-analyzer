# 偏好与成本 ⚙️

「偏好与成本」里的设置决定了比价表怎么算、怎么排、显示什么。这里的每一项都只影响本地计算，不会改变站点数据。

表单没有「保存」按钮，改了就走自动保存，输入停下约 0.4 秒落库，页面隐藏时补存一次，失败会弹红色提示。回到比价面板时面板会重拉数据。

## 显示与货币

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| `defaultCurrency` | `CNY` | 展示货币，可选 `CNY` / `USD` |
| `exchangeRate` | `7.3` | 人民币兑美元汇率，只用于换算 |

汇率可以手填，也可以点「从中国银行刷新」拉当日牌价。填了非法值会退回 7.3。

## 比价视图

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| `comparisonMode` | `paid` | `paid` 看付费中转站，`public` 看公益站 |

两种视图共用同一份采集数据，只是筛选范围不同。切换视图会改变「刷新全部」的目标集合。

## 推荐门槛

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| `evidenceThreshold` | `60` | 匹配置信度低于该值的报价不参与推荐 |

推荐只看月成本，不做成本与证据的加权打分：同一模型里只在国内付费站、官方匹配、成本可算的报价中挑最便宜的那条，其余按证据门槛标「需核验」或「可选」。存储里的 `recommendationProfile` 是历史遗留键，读取时会被清理。口径见[成本与推荐](../guide/cost#推荐)。

## 月用量

`usage` 存在存储里共 11 个键，设置页露出其中十项（`imageTokens` 是内部保留键，界面上不填）。token 类字段按百万 token 计，图片按张。默认值取 magpie 网关最近 30 天用量，按 30 天折算：

| 字段 | 默认值 |
| --- | --- |
| `input` | 326.81 M |
| `cacheRead` | 4434.31 M |
| `cacheWrite` | 1.91 M |
| `cacheWrite1h` | 0 |
| `output` | 28.98 M |
| `requests` | 54,378 |
| `peakShare` | 7/24 ≈ 0.29 |
| `imageInputTokens` / `imageOutputTokens` / `images` | 0 |

预设：

| id | 名称 | 内容 |
| --- | --- | --- |
| `recent30d` | magpie-30天 | 按 magpie 网关最近 30 天的用量折算成月用量，也是默认值 |
| `recent7d` | magpie-7天 | 按最近 7 天用量折算，变动大的月份更敏感 |
| `baseline` | 基础估算 | 3000 万输入 / 600 万输出，其余默认 |
| `custom` | 自定义 | 先选预设再逐项改 |

旧版本存过的 `measured`（实测月用量）预设已下线，读到那一组数值时会自动迁到当前默认用量。

### magpie 用量同步

两个 magpie 预设的数字来自本机网关 `GET /v1/magpie/usage?period=30d|7d`，不是写死的快照。扩展会按设置的间隔自动拉一次，也可以点「立即同步」手动触发。

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| `magpieBaseUrl` | `http://127.0.0.1:3425` | 只接受 `localhost` / `127.0.0.1` / `::1`，填别的会落回默认值 |
| `magpieSyncIntervalMinutes` | `360` | 可选 `0`（关闭）、`360`、`1440`；非法值落回 `360` |
| `magpieSync` | `null` | 同步结果快照，见下 |

`magpieSync` 每个窗口存 `{ usage, syncedAt, window }`，另有 `attemptedAt` 和 `error`。网关没开时只在 `error` 里记原因，已同步过的数字保留，不会清空。`usage` 只覆盖 `requests` / `input` / `cacheRead` / `cacheWrite` / `output` 五项，`peakShare` 和图像用量仍用设置里的值。

网关返回的是窗口内的总量，7 天窗口要乘 `30/7` 才是月用量。还没同步成功过时，两个预设退回内置快照（就是上面那张默认值表）。

预设的下拉文案会带同步日期，例如 `magpie-30天（11 月 16 日同步）`；没同步过时显示「内置快照」。

`peakShare` 是 0 到 1 的比例，不是百分比数字。填 `7` 会被夹到 `1`。

负值、空值、非数字一律落回预设默认值，不做报错。

## 匹配

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| `modelMatchOverrides` | 空 | 人工指定「站点模型 → 官方模型」 |
| `showUnmatched` | 开 | 没对上官方价的行是否进表 |

模型匹配由项目内置链路固定执行，历史设置里的 `matchingRules` 仅兼容读取，不再参与决策。规则链与优先级见[模型匹配](./matching)。

## 站点分类

站点挂在三个分类之一：

| id | 名称 |
| --- | --- |
| `benchmark` | 基准 |
| `paid` | 付费中转站 |
| `public` | 公益中转站 |

分类决定站点进哪个视图，也决定汇总口径。「基准」站点用来做参照，不参与推荐排序。

## 插件仓库

「插件仓库」视图管插件从哪来：

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| `pluginRegistry.url` | 官方 `plugins.json` | 仓库清单地址，可以换成自建；点「刷新仓库」重拉 |
| `pluginRegistry.entries` / `fetchedAt` / `error` | 空 / `0` / `""` | 最近一次拉取的清单内容、时间与错误，只读缓存 |
| `pluginRegistry.installed` | 空 | 已装插件记录，用来判断「有更新」 |
| `devMode` | `false` | 开发模式开关，打开后才出现「本地插件」面板 |
| `localPlugins` | `[]` | 只在本机加载的插件规格，关掉开发模式会一并卸载 |

「已安装」视图另有 `installed-select-all` 全选与「移除所选」。两处都支持 Shift 点勾选框选一整段。

## AI 辅助识别

「AI 辅助识别」用你自己的 OpenAI 兼容服务判断站点里的陌生模型名。判定只补规则猜不到的写法，不覆盖人工确认与插件声明，判过的结论进缓存，不重复请求。

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| `modelAssistant.enabled` | `false` | 关着时判定队列不动，也不会发请求 |
| `modelAssistant.baseUrl` | 空 | 服务地址，不写路径时自动补 `/v1` |
| 密钥 | 空 | 输入框是 `llm-api-key`，只进会话存储，浏览器重启后要重填，也不写进设置快照 |
| `modelAssistant.model` | 空 | 必须手填，可用「拉取列表」挑，不会自动选 |
| `modelAssistant.temperature` | `0.1` | 判定要稳定，建议 0 到 0.2 |

判定队列的四个按钮：

| 按钮 | 做什么 |
| --- | --- |
| `识别当前未匹配` | 把当前未匹配的模型写法去重后排队，一批 5 条并行请求（同时 6 批）。同写法同候选的站点条目只问一次，答案摊回各站点。单批超时 180 秒 |
| `全部重算` | 忽略缓存重跑一遍 |
| `接受的写成人工确认` | 把 AI 判成接受的写法批量写成 `modelMatchOverrides`，之后按人工覆盖优先；已经是人工指定的行不动 |
| `清空缓存` | 删掉判定缓存，队列回到未处理状态 |
队列按分区筛选，每页 20、50、100 条：

| 分区 | 里面是什么 | 能做什么 |
| --- | --- | --- |
| 已匹配 | 有结论且已经参与匹配的写法（含人工指定的） | 行尾「撤销」删掉这条判定，写法回到未匹配；也能用上面的按钮整批转成人工确认 |
| 未匹配 | 没有结论，或重试没到上限 | 点「识别当前未匹配」发给模型，或直接人工指定 |
| 待确认 | 试过但没定的：模型判成「清单里没有」、返回不存在的 id、重试到上限，以及请求超时与接口报错 | 点「重试」只重问这一条，或人工指定 |
| 全部 | 上面三类合起来 | 按写法或官方模型 id 过滤 |

每一行都能人工指定：点行尾「修改」，行内展开关键词搜索框，输入模型关键词（比如 `claude sonnet`）就列出匹配的官方模型，点一条即写入 `modelMatchOverrides`，徽标变「人工指定」。人工指定优先级最高，规则层和模型都不会覆盖；行尾「撤销」取消人工指定，写法回到人工覆盖之外再看。

失败行第二列直接写原因（请求超时 / 接口报错 / 模型没答这条）。超时算环境问题，不计入重试上限，一直留在待确认。
已接受的写法如果又出现在未匹配里（官方清单换了、id 失效），行上会标「已失效」。

## 关于与更新

「关于」分区放版本信息、更新检测和项目链接，数据来自 GitHub Releases，不上报任何本地数据。

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| `updateAutoCheck` | `true` | 是否按间隔在后台静默检查 |
| `updateIntervalMinutes` | `360` | 检查间隔，只接受 `60` / `360` / `1440` 分钟 |
| `updateChannel` | `stable` | `stable` 只提示正式发布，`prerelease` 连预发布一起提示 |

改动即时生效：关掉自动检查会清掉 `update-check` 定时任务，改间隔会按新周期重建。最近一次检查结果单独存 `update-state`，不写进设置。

「检查更新」先读公开的 `github.com/<仓库>/releases/latest` 页面（`prerelease` 渠道读 `releases` 列表），从跳转后的地址或页面链接里取 tag，再和本地 `manifest.json` 的 `version` 按语义化版本比较。页面不带发布说明，所以拿到版本后还会试一次 `api.github.com` 补说明，接口不通就留空，不影响「有没有新版本」的结论。仓库还没发过版本时 GitHub 返回 404，界面显示「仓库还没有发布版本」，不当错误处理。走页面是因为未登录的接口配额只有每小时 60 次，撞上限时提示剩余恢复时间（读 `X-RateLimit-Reset`）；自动检查在恢复时间前直接跳过，不重复消耗配额。

## 不会被恢复的旧设置

老版本的 `llm`、`jev`、`providerProfiles`、`activeProviders` 在保存时会被清掉。这些功能已经下线，不要再往设置里塞回去。
