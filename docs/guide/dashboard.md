# 价格对比 📊

价格对比面板是主界面。它把站点快照、官方参考价、汇率和你的用量口径拼成一张表：一行是「一个站点 + 一个分组 + 一个模型」的报价。

## 顶部

| 元素 | 作用 |
| --- | --- |
| MODEL ATLAS · 价格对比 | 站点名与页面标题 |
| 状态点 + `更新于 hh:mm:ss` | 最新快照的采集时间；没有数据时显示「尚未刷新」 |
| 站点与设置 | 跳到 `options.html#stations` |
| 展开全部 / 折叠全部 | 展开或收起侧栏里的卡片 |
| 刷新全部 | 触发预检与采集，见[采集价格](./collection) |
| 刷新当前站点 | 站点筛选选中某站后才可点，只采这一站，不走预检 |

标题下面一排是**比较来源**：`付费中转站` 和 `公益站`，两种模式各自独立刷新、独立比价，切换不会丢数据。

## 预检面板

点过「刷新全部」之后，页面上方出现「页面登录状态」面板：

- 首行状态文字说明当前分组有几个启用站点。
- 下面列出每个站点的预检结果与原因。
- 两个按钮：`取消` 和 `确认开始刷新全部`。确认才真正采集。

## 采集进度

采集开始后出现「采集进度」：进度条、`N / M 站点`、当前在采的站点，以及每站的成败列表。进度靠 `REFRESH_PROGRESS` 消息推送，不是定时轮询；service worker 被回收就停住。

## 统计卡

顶上四张卡，内容的含义随模式变：

| 付费模式 | 公益模式 |
| --- | --- |
| 覆盖模型：去重后的模型数，附 `N 条报价 · M 个启用站点` | 公益模型：模型数，附报价条数与站点数 |
| 官方匹配：有官方参考价的条数，附匹配率百分比 | 公益站点：站点数 |
| 首选方案：被标成推荐的报价条数 | 价格单位：站点积分 / 额度，首版按 1:1 展示 |
| 需核验：未匹配、推导、过期、部分解析、价格缺失的总数，附原因分类 | 数据状态：需核验条数与原因 |

## 筛选与排序栏

侧栏第一块是「筛选和排序」：

| 控件 | 作用 |
| --- | --- |
| 搜索框 | 同时匹配模型写法、站点名、供应商 |
| 全部中转站 | 单站点筛选，里面还有搜索框；站点名后面挂 `×0.62` 这类折扣中位数，样本不足 3 个模型不显示 |
| 供应商 | 多选，带「全选 / 清空」和搜索 |
| 分组 | 多选，带「全选 / 清空」和搜索 |
| 排序方式 | 分组、官方源、模型名称、月成本、混合单价（默认）、相对官方、匹配置信度 |
| 排序方向 | 升序（默认）/ 降序 |
| 次级排序 | 相对官方（默认）、模型名称、月成本、混合单价、匹配置信度、不使用 |
| 更新官方价 | 手动刷新官方参考价与汇率 |
| 重置 | 清掉全部筛选与排序条件 |
| 模型对比 | 展开一组输入框，按模型逐个填值筛选 |
| 显示未匹配 | 勾上后，没有官方参考价的模型也进表 |
| 显示过期 | 默认勾上；关掉只看 `success` / `partial` 且 30 分钟内的数据 |

`官方源`、月成本、混合单价、相对官方这几项在公益模式下不适用，相关按钮与列由 `paid-only` 类隐藏。

## 价格明细表

### 列

| 列 | 内容 |
| --- | --- |
| 模型 / 官方匹配 | 模型名 +（付费模式下）供应商标签；下面一行是 `匹配 <官方名> · <匹配规则> · 置信 N%`，没对上就写「没有对应的官方目录记录」 |
| 中转站 / 分组 | 站点名（可点，点了就按该站筛选）、站点类别（付费中转站 / 公益站）、分组名、`tier · 倍率 ×N` |
| 中转币 / M token | 站点报的各档单价（输入、输出、缓存读写等），带币种 |
| 官方单价 | 有官方价时显示官方各档单价，付费模式专有 |
| 月成本 | 按你的月用量算出的月成本，附「官方 ¥x / 月」对比，以及「月省 / 月多付 ¥x」 |
| 相对官方 | `低 x%` / `高 x%` / `持平`，无官方价时显示「无官方价」或具体缺失原因 |
| 混合单价 | 月成本 ÷ 计费 token 总量，右侧标 `按 缓存读:输入:输出 混合` 与官方混合单价；公益站不输出 |
| 推荐与状态 | 推荐标签、评级标签、`价格齐全 / 含推导：… · 置信 N%`、状态标签 |
| 状态 | 公益模式下单独一列，只放状态标签 |

推荐标签来自 `core/pricing.js`：同模型下月成本最低且证据够的标 `推荐`，其余够格的标 `可选`，置信度低于推荐门槛（默认 60，可在设置里改）的标 `需核验`。

评级标签：`神价`、`折扣`、`公道`、`溢价`。

状态标签（`statusMarkup`）：

| 标签 | 什么时候出现 |
| --- | --- |
| `已校准` | 没有下面任何一条 |
| `过期` | 快照超 30 分钟或状态不是 success / partial |
| `未匹配` | 付费模式下没有官方价对应记录 |
| `价格推导` | 价格是从别的档位推算出来的（`evidence === "estimated"`） |
| `部分解析…` | 快照是 partial，后面会跟未解析的计费方式、异常价格字段、未定价模型 |
| `币种待核验` / `缺少 1 小时缓存价` / `中转价格未收录` | 价格缺失的具体原因 |

### 行数、分页与滚动

- 右上角显示 `N 条报价`，是筛选后的条数。
- 分页每页可选 20（默认）、50、100、200、500 条，带上一页 / 下一页和页码。
- 表格可横向滚动，宽度不够时按列读。

### 空状态

没数据时表面换成一句提示，文案随情况变：没加站点、加了但没采集、公益模式下没有公益站。

## 每日签到面板

侧栏第二块，只在有可签到站点时出现。详见[每日签到](./checkin)。

## 刷新之后该看什么

1. 先看统计卡的「需核验」，它是所有可疑行数的汇总。
2. 再看状态标签，按 `未匹配` → `部分解析` → `过期` 的顺序处理。
3. 月成本不合预期时，去[成本与推荐](./cost)核对用量与计价口径，而不是怀疑采集。
