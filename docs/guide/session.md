# 登录与会话 🔐

有些站点的价格接口公开，有些要先登录。默认情况下扩展不碰你的账号密码，只复用浏览器里已有的登录状态；只有在站点配置里填了 `basic` 认证字段时，才会把那一组用户名密码存在本地。

## 两种采集通道与登录的关系

| `mode` | 怎么拿数据 | 需要登录吗 |
| --- | --- | --- |
| `direct` | 后台直接请求站点的价格接口 | 通常不需要；接口要求带 token 时用下面的认证设置，或走 cookie 登录态换 token |
| `page` | 在已打开的站点标签页里注入脚本，读页面数据 | 需要，且你自己先在该标签页登录 |

`page` 模式读的是当前浏览器配置里的登录态（cookie + 页面里的 token），扩展不会把令牌写到本地存储再用到别处。

## 直接模式的认证

`auth.type` 四种：

| 类型 | 请求头 | 什么时候用 |
| --- | --- | --- |
| `none` | 无 | 公开价格页 |
| `bearer` | `Authorization: Bearer <token>` | 站点给的是 API Key 形式的令牌 |
| `api-key` | `X-API-Key: <token>` | 站点要求专用头 |
| `basic` | `Authorization: Basic ...` | 用账号密码校验的接口 |


令牌存在扩展本地存储里，换设备要重填。`basic` 的密码同样是明文本地存储，别把共享机器的浏览器配置当凭据库用。

## cookie 登录态后台换 token

有一类站点的登录态只存在 HttpOnly cookie 里，页面里读不到 token，刷新接口还会校验 `Origin`。这类站点仍是 `direct` 模式，扩展在 service worker 里借 `declarativeNetRequest` 给刷新请求补齐 `Origin` 与 `Cookie`，换出 access token 后再请求价格接口。

- 登录还是在站点页面上做一次，扩展不碰账号密码。
- 换到的 token 只在内存里用于这一轮采集，不写进本地存储。
- token 过期后自动再换一次，不用重新登录，也不用把站点标签页一直开着。

站点侧这套声明写在插件的 `cookieRefreshAuth` 里（`cookieName`、`refreshPath`、`accessTokenPath`、`expiresAtPath`），由 `plugin-build.mjs` 生成进扩展。

## 刷新预检

点「刷新全部」之前会先跑一次预检，把启用的站点分成四类：

| 标签 | 含义 | 处理 |
| --- | --- | --- |
| 已登录 | 探测请求成功 | 直接进采集 |
| 需要登录 | 返回 401/403 或跳登录页 | 去站点登录，或改用 `page` 模式 |
| 需人工确认 | 结果无法判定 | 自己打开站点看一眼 |
| 无需登录 | 公开接口 | 直接进采集 |

有「需要登录」时，刷新不会直接跑，要你先确认。预检正常也会再问一次，避免误刷。

## 会话过期

| 症状 | 原因 | 处理 |
| --- | --- | --- |
| 昨天能采，今天「需要登录」 | cookie 过期或站点改了登录 | 打开站点重新登录 |
| `page` 模式一直空 | 标签页不在前台、或选错了标签页 | 让目标站点标签页保持打开 |
| cookie 登录态的站点仍提示「需要登录」 | 站点的登录 cookie 已被清掉，后台换 token 失败 | 打开站点登录一次，之后扩展自己续期 |
| 签到显示「未登录」 | 签到复用的是站点登录态 | 点「打开站点登录」，扩展会在 6 分钟内每 30 秒探一次状态，成功后自动存快照 |
| 站点要求人机校验 | 站点有反自动化 | 纯手工，扩展不做绕过 |

## 安全边界

- 扩展只在你授权过的站点域名上发请求。
- `page` 模式的脚本只注入到目标站点的标签页，不跑在别的页面上。
- 站点返回的内容一律当数据，不执行其中的脚本。
- 详见[隐私与安全](../security)。
