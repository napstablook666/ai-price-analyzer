# 登录与会话 🔐

有些站点的价格接口公开，有些要先登录。扩展不存你的账号密码，只复用浏览器里已有的登录状态。

## 两种采集通道与登录的关系

| `mode` | 怎么拿数据 | 需要登录吗 |
| --- | --- | --- |
| `direct` | 后台直接请求站点的价格接口 | 通常不需要；接口要求带 token 时用下面的认证设置 |
| `page` | 在已打开的站点标签页里注入脚本，读页面数据 | 需要，且你自己先在该标签页登录 |

`page` 模式读的是当前浏览器配置里的登录态（cookie + 页面里的 token），扩展不会把令牌写到本地存储再用到别处。

## 直接模式的认证

`auth.type` 四种：

| 类型 | 请求头 | 什么时候用 |
| --- | --- | --- |
| `none` | 无 | 公开价格页 |
| `bearer` | `Authorization: Bearer <token>` | 站点给的是 API Key 形式的令牌 |
| `api-key` | `X-API-Key: <token>` | 站点要求专用头 |
| `basic` | `Authorization: Basic ...` | 用账号密码校验的接口 |

令牌存在扩展本地，不写进导出文件，也不出现在导出的 JSON 里。

## 刷新预检

点「刷新全部」之前会先跑一次预检，把启用的站点分成四类：

| 标签 | 含义 | 处理 |
| --- | --- | --- |
| 已登录 | 探测请求成功 | 直接进采集 |
| 需要登录 | 返回 401/403 或跳登录页 | 去站点登录，或改用 `page` 模式 |
| 需人工确认 | 结果无法判定 | 自己打开站点看一眼 |
| 无需登录 | 公开接口 | 直接进采集 |

有「需要登录」时，刷新不会直接跑，要你先确认。预检正常也会再问一次，避免误刷。

## 会话过期

| 症状 | 原因 | 处理 |
| --- | --- | --- |
| 昨天能采，今天「需要登录」 | cookie 过期或站点改了登录 | 打开站点重新登录 |
| `page` 模式一直空 | 标签页不在前台、或选错了标签页 | 让目标站点标签页保持打开 |
| 签到停在「待登录」 | 签到复用的是页面登录态 | 先登录再等下一次定时 |
| 站点要求人机校验 | 站点有反自动化 | 纯手工，扩展不做绕过 |

## 安全边界

- 扩展只在你授权过的站点域名上发请求。
- `page` 模式的脚本只注入到目标站点的标签页，不跑在别的页面上。
- 站点返回的内容一律当数据，不执行其中的脚本。
- 详见[隐私与安全](../security)。
