# 隐私与安全 🛡️

没有服务端，没有账号体系。扩展只做三件事：读站点公开数据、算本地账、把结果画出来。

## 数据在哪

| 数据 | 位置 | 会不会离开本机 |
| --- | --- | --- |
| 站点配置（地址、端点、标签） | 浏览器本地存储 | 只有你自己导出时 |
| 登录凭据（token、账号密码） | 浏览器本地存储，不写入工作区 | 只在请求对应站点时发出 |
| 采集快照与价格 | 本地存储 | 否 |
| 设置与月用量 | 本地存储 | 否 |
| 工作区文件 | 你选的目录 | 取决于你是否同步该目录 |

## 权限说明

`manifest.json` 声明：

```json
{
  "permissions": ["alarms", "scripting", "tabs", "storage"],
  "host_permissions": ["<all_urls>"]
}
```

| 权限 | 干什么用 |
| --- | --- |
| `storage` | 存配置与快照 |
| `alarms` | 每日签到的定时任务 |
| `scripting` | `page` 模式往站点标签页注入读取脚本 |
| `tabs` | 找到目标站点已打开的标签页 |
| `<all_urls>` | 中转站域名没法预先枚举，只能申请全站 |

全站权限是形态决定的，不是想多要。实际请求受两重限制：

- 只在**启用的站点**配置的 `baseUrl` 域名上发请求。
- 只接受 `https://`；明文 `http://` 仅允许 `localhost`、`127.0.0.1`、`::1`。

## 不会做的事

- 不把数据发往任何第三方服务器。
- 不上传快照、不上传凭据、不做遥测。
- 不执行站点返回的脚本，响应一律按数据解析。
- 不绕过人机校验，不模拟登录。
- 不读写你未配置的域名。

## 唯一会写站点的地方

每日签到。它在目标站点下调一次签到接口，属于对站点的写操作。不开这个开关就完全不写。

## 凭据的实际暴露面

- 凭据存在本地存储，能读到扩展存储的人就能读到它，这和浏览器保存密码同级。
- 凭据会出现在对目标站点的请求头里，不会出现在其他站点的请求里。
- 工作区与导出的 JSON 已抹掉凭据，只留 `auth.type`。

## 出了漏洞怎么报

按 `SECURITY.md` 的流程走私密报告，别开公开 issue，别贴真实 token。报告里给版本号、复现步骤、影响面。
