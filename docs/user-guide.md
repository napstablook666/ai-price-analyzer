# 使用手册

AI Price Analyzer 是一个无需构建的 Chromium MV3 扩展。它从已配置的 AI 中转站采集模型价格，把不同站点的模型写法归一到同一个模型身份，再在本地面板中进行比较。

## 1. 安装

### 从 Release 安装

1. 从 GitHub Release 下载 `ai-relay-price-extension-v<version>.zip`。
2. 解压 ZIP。要加载的目录必须直接包含 `manifest.json`。
3. 打开基于 Chromium 的浏览器，访问 `chrome://extensions`。
4. 打开“开发者模式”，点击“加载已解压的扩展”，选择解压后的目录。
5. 固定扩展图标，方便打开弹窗和对比面板。

### 从源码安装

源码仓库根目录就是可加载的扩展目录。项目当前不需要 bundler、Docker、Playwright 或第三方运行时依赖。

1. 克隆扩展仓库。
2. 打开 `chrome://extensions`。
3. 选择源码仓库根目录执行“加载已解压的扩展”。
4. 修改源码后，在扩展管理页点击扩展的刷新按钮。


## 2. 第一次使用

1. 点击扩展图标，选择“站点与设置”，或打开扩展的对比面板。
2. 在“站点与设置”中添加一个站点网址。
3. 等待站点分析完成，检查扩展建议的主机、接口、认证方式和采集模式。
4. 确认保存站点。
5. 回到对比面板，点击“刷新全部”。
6. 在表格中查看模型、站点价格、匹配状态和比较结果。

建议先只添加一个站点完成一次采集，再批量添加其他站点。这样更容易判断是站点配置问题还是页面/接口临时变化。

## 3. 添加站点

设置页支持两类来源：

- **插件目录中的已知站点**：选择站点插件提供的默认模板，再按页面提示补充地址或认证信息。
- **自定义站点地址**：输入站点 URL，让扩展分析可用的路径和接口，再人工确认建议配置。

保存前重点检查：

- 主机名和路径是否指向实际价格页面或接口。
- 采集模式是否正确。
- 是否需要当前浏览器登录态。
- 价格单位和币种是否与站点页面一致。
- 站点是否应归入“付费中转站”或“公益站”。

站点只在启用后参与刷新。暂时不想采集某个站点时，优先关闭它，不必删除配置。

## 4. 选择采集模式

### 直接接口

直接接口模式由扩展请求站点配置的 JSON 接口，适合公开、允许扩展请求的接口。

遇到以下情况时优先检查：

- 接口 URL 是否已经失效。
- 站点是否要求 Cookie、Token 或额外请求头。
- 浏览器是否拦截了跨域请求。
- 返回内容是否仍然是 JSON，而不是登录页或错误页。

### 页面桥接

页面桥接模式通过当前浏览器标签页中的页面上下文发起请求，适合依赖浏览器 Cookie、localStorage 或登录页面的站点。

使用步骤：

1. 在站点页面登录。
2. 保持该站点页面打开，不要切换到不相关的同源页面。
3. 在扩展中保存或确认该站点配置。
4. 点击“刷新全部”或“刷新当前站点”。
5. 如果出现“页面登录状态”预检，先登录或检查对应标签页。
6. 预检完成后，点击“确认开始刷新全部”。

预检只负责确认页面会话和采集范围。它不会代替最终的价格采集，也不会把站点密钥写入导出文件。

## 5. 刷新与比较

对比面板顶部有两个比较来源：

- **付费中转站**：保留官方参考价、月成本、差价和推荐逻辑。
- **公益站**：只比较公益站之间的报价，金额表示站点积分或额度，默认按 1:1 展示，不与官方价格混合。

刷新按钮：

- **刷新全部**：刷新当前比较分组中所有启用站点。包含页面登录态的站点会先执行预检。
- **刷新当前站点**：只刷新当前筛选的站点，不改变其他站点的快照。

刷新完成后，表格会显示最新快照中的模型和价格。站点请求失败时，先查看站点状态、错误摘要和采集时间，再决定是否重试。

## 6. 阅读比价表

表格中的模型名来自统一模型身份。不同站点的写法，例如带厂商前缀、`:free`、`:thinking` 或日期后缀的写法，可能会被归到同一个规范模型。

常见字段：

- **模型**：站点原始写法归一后的显示名称。
- **中转站 / 分组**：站点名称以及付费或公益分组。
- **中转单价**：站点当前快照中的输入、输出或其他可比较价格。
- **官方单价**：付费比较模式下的公开参考价格；公益模式不显示该列。
- **匹配状态**：是否找到规范模型或人工确认的匹配。
- **月成本 / 推荐**：在付费比较模式下，根据当前使用量设置计算的比较结果。

如果模型没有找到官方匹配价，不要手动把它改成看起来相近的模型。可以先在设置中确认模型写法，再使用人工匹配覆盖；插件维护者则应把稳定的站内别名写入对应插件的 `models.json`。

## 7. 参考数据与成本口径

付费比较模式可能使用：

- OpenRouter 的公开模型目录和价格。
- 中国银行外汇牌价页面中的汇率参考。
- 设置页中的使用量、充值金额和站点价格配置。

参考数据刷新失败时，已有缓存不会自动变成新数据。先检查网络和来源页面，再重试刷新参考数据。

公益比较模式不使用官方价格列。公益站之间的价格只在同一公益比较范围内展示，避免把积分或额度误当成现金价格。

## 8. 工作区与 JSON 备份

设置页提供两种本地数据管理方式：

- **本地工作区**：选择一个文件夹，按页面提示从工作区加载或保存数据。
- **JSON 备份**：使用“导出 JSON”保存状态，使用“导入 JSON”恢复状态。

导出文件不包含站点密钥和 API Key。导入后，需要在设置页重新填写被剥离的密钥，并重新检查页面模式站点的登录状态。

备份建议：

1. 在批量修改站点前先导出一次 JSON。
2. 为备份文件写上日期和用途，不要把它提交到 Git。
3. 不要把包含真实站点地址、账户标识或响应内容的备份上传到 Issue、聊天或公共网盘。
4. 导入失败时保留原文件，不要覆盖原有备份。

## 9. 常见故障

### 刷新后没有报价

- 确认站点已启用。
- 确认当前比较模式与站点分组一致。
- 直接接口模式检查接口地址和响应内容。
- 页面桥接模式打开站点页面并重新登录。
- 查看站点的错误摘要和最后采集时间。

### 站点需要登录

在页面桥接模式下，先打开站点页面并完成登录。回到扩展后重新运行页面登录状态预检，再确认刷新。

### 模型显示为未匹配

这是模型身份无法由规范表、插件别名或已有规则确定的提示。先确认站点返回的原始模型名，再检查是否只是前缀、版本、地区或计费后缀差异。不要用近似名称强行覆盖。

### 修改插件后扩展行为没有变化

插件源码不是扩展运行时直接读取的文件。修改独立插件仓库后，必须从扩展仓库运行：

```bash
node scripts/plugin-build.mjs
```

然后重新加载扩展。生成文件位于 `src/site-plugins/`，不要手改这些生成物。

### 导入后密钥失效

这是预期行为。导出和导入流程会剥离站点密钥及 API Key。重新填写密钥后，再执行一次站点预检或单站刷新。

## 10. 反馈问题时如何脱敏

报告站点适配问题时，请保留：

- 扩展版本和 Chromium 版本。
- 站点插件 ID 或站点主机名。
- 采集模式：`direct` 或 `page`。
- 复现步骤和出现问题的页面路径。
- 响应的字段结构、数组层级和类型。

删除以下内容：

- Cookie、Authorization、Token、API Key、签名和密码。
- URL 中的用户名、密码、私有查询参数和临时授权参数。
- 账户 ID、订单号、余额、私有模型列表和完整响应正文。
- 未经确认的私有站点链接。
